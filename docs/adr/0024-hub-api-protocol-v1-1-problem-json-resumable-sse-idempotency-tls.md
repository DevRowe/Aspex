# Protocol v1.1: problem+json errors, resumable SSE, Idempotency-Key alignment, optional TLS

The Hub API is the asset every Aspex client shares, and the review/platform scouting (giles tasks `aspex-review-ux-r3` Part 2 B, `aspex-ar-platforms-k5` Part 2 Decision 1) converged on hardening it now, while the only consumers are in-house and additive change is cheap.
**Protocol v1.1 is an additive pass: RFC 9457 error bodies, resumable SSE, IETF-aligned idempotency, an `apiVersion` field, and optional TLS - with the wire protocol otherwise unchanged.**
`docs/hub-api.md` is the client-facing contract; this ADR records the decisions.

- **RFC 9457 problem+json for every error body.** Agent clients branch on a `type` URI instead of parsing prose.
  Generic errors are `about:blank`; only client-branchable conditions get named `urn:aspex:problem:*` types (`confirmation-required`, `idempotency-key-mismatch`, `same-key-different-payload`).
  Every problem keeps a legacy `message` extension so pre-v1.1 clients that read `body.message` keep working.
- **The 409 confirmation gate is KEPT, and made machine-readable.** The user decision (ar-platforms Decision 1) is to keep 409-until-confirmed and defer the 202 + pending-approval object until a second simultaneously-active direction client exists.
  The `confirmation-required` problem carries `itemId`/`actionId` (or `verb`/`intentId`/`orchestrator`), a restated `summary`, and `resend` - the exact body the confirm call must POST back - so no client parses prose to build the confirm.
- **SSE is resumable.** One broadcaster per app assigns monotonic `id:`s, encodes each event once, and keeps a bounded replay ring (256 events); `Last-Event-ID` replays exactly the missed frames or falls back to a fresh snapshot; the server sends `retry:`; keepalives are a named `ping` event instead of a `: ping` comment.
  The bus subscription is now permanent rather than attached-while-subscribed: buffering while no client is connected is precisely what makes reconnect resume work, at the cost of one ranked-snapshot encode per world event with zero clients (low-rate, acceptable).
- **Idempotency aligns with the IETF draft, keeping `intentId` as the domain id.** The `Idempotency-Key` header is accepted (bare or quoted) and must agree with the body `intentId` when both are present; a stored request fingerprint turns same-key-different-payload reuse into a 422; replays and in-flight joins are marked `Idempotency-Replayed: true`; retention stays the 1024-entry LRU, documented rather than time-bounded, because the orchestrator inbox filename is the durable dedupe backstop.
- **`apiVersion` in `GET /state`, no `/v1` prefix.** Additive-only evolution plus documented ignore-unknown-fields/events rules; the version field is the cheap insurance, reserved before the Giles-side consumer hardens.
- **Optional TLS for the tailnet exposure.** Snap requires wss/https to publish, Meta's web-app path and Chrome 142 Local Network Access push the same way, so the Hub takes a `tls: { certPath, keyPath }` config (or `ASPEX_HUB_TLS_CERT`/`ASPEX_HUB_TLS_KEY`), reads the PEMs at boot (fail-fast), and serves https on the same port.
  Cert provisioning stays manual and documented (`tailscale cert`, or `tailscale serve` in front of a loopback Hub); auto-renewal/reload is explicitly out of scope for a single-operator daemon.

We rejected **migrating the gate to 202 + pending-approval now** (multi-party approval infrastructure with expiry/listing/cross-client identity that nothing consumes yet; the problem type keeps the eventual break small), **a `/v1` path prefix** (premature for a single-vendor local API; additive evolution plus `apiVersion` suffices), **time-based idempotency retention** (a TTL adds clockwork for no real guarantee the LRU does not already give), and **building TLS auto-renewal into the Hub** (tailscale already owns that lifecycle; the Hub restarting on renewal is an acceptable manual step).
The cost is a permanently-attached SSE encoder (one snapshot per world event even with no clients) and problem bodies that are heavier than `{ message }` - accepted for a protocol meant to be consumed by machines first.
